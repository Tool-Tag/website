# Photo proof follow-up

## Photos

All four file-input components share local HEIC/HEIF-to-JPEG normalization. The decoder is loaded on demand in the browser; photos are not sent to an external conversion service. The first image is used for multi-image HEIF files. PNG/JPEG/WebP files are unchanged. Existing validation runs after normalization: payment/expense proof remains 3.5 MB; quote artwork and optional intake tool photos retain their existing 3 MB limit. Unsupported or corrupt HEIC files show an English error rather than uploading an unreadable original. Payment/refund proof remains file-selection only.

Completed Evidence uses the photo picker without the redundant generic Upload File disclosure; its submit label is Upload.

## Accepted agreement copies

Apply the new additive migration `20261018202614_public_agreement_document_resend.sql` before enabling this feature in production. It has not been applied by this implementation. No applied migrations or Agreement text were changed.

The status-token RPC only queues the customer-visible accepted agreement belonging to that status link. It emails the frozen accepted recipient, never an address supplied by the browser or subsequently edited customer information. The mail worker attaches the existing stored PDF after verifying its SHA-256; it does not regenerate the document. The sender uses the Quotes department configuration. Local disabled/test modes do not enable the public resend action. No SMS is generated by this email-only event.

Requests are idempotent by UUID, serialized by an accepted-document row lock, limited to one per 90 seconds and ten per day. Pending or uncertain deliveries block another copy. Existing queue claim/result handling records Gmail failures. The UI says queued, not delivered. A Gmail outage does not affect the accepted document.
